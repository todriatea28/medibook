📋 1. პროექტის არსი და ბიზნეს-კონცეფცია
🎯 პროექტის მიზანი და გადაჭრილი პრობლემა
Medihub არის თანამედროვე ციფრული სამედიცინო პლატფორმა, რომელიც პაციენტებსა და კლინიკებს შორის კომუნიკაციას ამარტივებს. აპლიკაცია აგვარებს ექიმთან ვიზიტის დაჯავშნის, რიგების მართვის, სპეციალისტების ძებნისა და სამედიცინო ისტორიის (დიაგნოზები და დანიშნულებები) თვალყურის დევნების სირთულეებს, უზრუნველყოფს რა ერთიან, ინტუიციურ სივრცეს.

👥 სამიზნე მომხმარებლები და მათი როლები
პაციენტები: ეძებენ ექიმებს სპეციალობისა და კლინიკის მიხედვით, ჯავშნიან ვიზიტებს, აკონტროლებენ მათ სტატუსებს, იღებენ ელექტრონულ დიაგნოზს/დანიშნულებას და აფასებენ ექიმებს ვიზიტის დასრულების შემდეგ (1-5 ვარსკვლავიანი შეფასების სისტემით).
ექიმები / ადმინისტრატორები: მართავენ თავიანთ სამუშაო განრიგს, პაციენტების ვიზიტებს (დადასტურება, გაუქმება, დასრულება), წერენ დიაგნოზებსა და სამედიცინო დანიშნულებებს.
🔄 2. მომხმარებლის ნაკადისა და ფუნქციონალის ანალიტიკა
🗺️ მომხმარებლის გზა (User Flow - Happy Path)
ავტორიზაცია/რეგისტრაცია: მომხმარებელი შედის სისტემაში (როლი: პაციენტი ან ექიმი).
ძებნა და ფილტრაცია: პაციენტი ეძებს ექიმს სახელით ან ფილტრავს სპეციალობის მიხედვით.
ვიზიტის დაჯავშნა: ირჩევს სასურველ თარიღსა და დროს, ავსებს ფორმას და ჯავშნის ვიზიტს.
სტატუსის მართვა: ექიმი ადასტურებს ვიზიტს, ხოლო კონსულტაციის შემდეგ ამატებს დიაგნოზს/ნოტებს და ასრულებს ვიზიტს.
შეფასება: დასრულებული ვიზიტის შემდეგ პაციენტი ტოვებს შეფასებას.
🛠️ ძირითადი ფუნქციონალი (CRUD & ინტერაქცია)
Create: ახალი ვიზიტის დაჯავშნა, ექიმის შეფასების დამატება.
Read: ექიმების სიის, ხელმისაწვდომი სლოტების, ვიზიტების ისტორიისა და დიაგნოზების ნახვა.
Update: ვიზიტის სტატუსის ცვლილება (pending ➔ confirmed ➔ completed / cancelled), დიაგნოზისა და დანიშნულების ჩაწერა.
Delete: ვიზიტის გაუქმება პაციენტის ან ექიმის მიერ.
🏗️ 3. ტექნიკური არქიტექტურა და State Management
🛠️ ტექნოლოგიური სტეკი
Frontend Framework: React 19 (Vite)
Styling: Tailwind CSS (Burgundy/Stone პალიტრა, Glassmorphic UI)
Global State: Zustand (persist middleware)
Backend & Auth: Supabase (PostgreSQL & Row Level Security - RLS)
Icons & Routing: Lucide React, React Router v6
📁 საქაღალდეების სტრუქტურა
src/
├── components/      # მოდულარული UI კომპონენტები (Navbar, DoctorCard, RatingModal...)
├── context/         # AuthContext (ავტორიზაცია)
├── hooks/           # Custom Hooks (useDoctorSearch...)
├── pages/           # აპლიკაციის გვერდები (PatientDashboard, DoctorDashboard...)
├── services/        # Supabase API სერვისები (doctorService, appointmentService)
└── store/           # Zustand ცენტრალური გლობალური სთეითი (useMediStore.js)

💾 სთეითის სინქრონიზაცია (Single Source of Truth & LocalStorage)
პროექტში ლოკალური useState-ები შეიცვალა ცენტრალიზებული Zustand Store-ით (useMediStore). Zustand-ის persist middleware უზრუნველყოფს მონაცემების ავტომატურ სინქრონიზაციას ბრაუზერის localStorage-თან (medibook-storage), რისი მეშვეობითაც გვერდის გადატვირთვისას (Refresh) მონაცემები არ იკარგება.
⚡ 4. წარმადობა, უსაფრთხოება და ტესტირება
🚀 ოპტიმიზაცია
Debounced Search: ძებნის ველში useDoctorSearch ჰუკის გამოყენებით შემცირებულია ზედმეტი რე-რენდერები.
Vector Assets: გამოყენებულია მსუბუქი ვექტორული SVG იკონები (lucide-react).
🛡️ დაცვითი მექანიზმები (Defensive Programming)
ErrorBoundary: იცავს აპლიკაციას კოლაფსისგან ("თეთრი ეკრანი").
Offline / Fallback რეჟიმი (isFallback): სერვერის მიუწვდომლობისას აპლიკაცია ავტომატურად გადადის ლოკალურ დემო მონაცემებზე და აფრთხილებს მომხმარებელს (TriangleAlert).
Double-Click Protection: ფორმების გაგზავნისას და ვიზიტის გაუქმებისას ჩაშენებულია დადასტურების მექანიზმები.
🌐 კროს-ბრაუზერული და რესფონსივ ტესტირება
Responsive: ტესტირებულია DevTools Device Mode-ით. ინტერფეისი იდეალურად ადაპტირდება დესკტოპზე (1440px), პლანშეტზე (768px) და მობილურზე (375px).
Cross-Browser: წარმატებით ჩატარდა ტესტირება Google Chrome და Mozilla Firefox ბრაუზერებში. მარშრუტები, ფილტრაცია და ვიზიტების მართვა მუშაობს იდენტურად.
