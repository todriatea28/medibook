### 1. პროექტის რეზიუმე და ამოცანა

- **მიზანი:** MediBook არის თანამედროვე ციფრული სამედიცინო პლატფორმა, რომელიც უზრუნველყოფს პაციენტებისა და ექიმების ეფექტურ ურთიერთქმედებას. სისტემა საშუალებას აძლევს პაციენტებს მოძებნონ ექიმები სპეციალობისა და კლინიკის მიხედვით, დაჯავშნონ ვიზიტები, თვალყური ადევნონ სტატუსებს, მიიღონ დიაგნოზები და დანიშნულებები, ასევე შეაფასონ ექიმები ვიზიტის დასრულების შემდეგ.
- **ტექნიკური სტეკი:** React, Vite, Tailwind CSS, Zustand (Global State & Persist Middleware), Supabase (PostgreSQL & RLS), Lucide React, React Router.

---

### 2. არქიტექტურა და კომპონენტური იერარქია

- **საქაღალდეების სტრუქტურის აღწერა:**
  - `src/components/`: მოდულარული და მრავალჯერადი გამოყენების UI კომპონენტები (`Navbar`, `Footer`, `DoctorCard`, `RatingModal`, `NotificationBell`, `ScheduleEditor`).
  - `src/pages/`: ძირითადი გვერდები (`PatientDashboard`, `DoctorDashboard`, ავტორიზაციის და რეგისტრაციის გვერდები).
  - `src/store/`: ცენტრალური გლობალური სთეიթი (`useMediStore.js`).
  - `src/services/`: ბაზასთან კომუნიკაციისა და სერვისების ფენა (`doctorService.js`, `appointmentService.js`).
- **გლობალური სთეიթი და მეხსიერება:** პროექტში გამოიყენება Zustand-ის `persist` middleware. ეს უზრუნველყოფს სთეითის (ექიმები, ვიზიტები, ძებნის ველები და ფილტრები) ავტომატურ სინქრონიზაციას ბრაუზერის `localStorage`-თან (`medibook-storage`), რათა გვერდის გადატვირთვისას (`Refresh`) მომხმარებლის მონაცემები არ დაიკარგოს და შენარჩუნდეს ერთიანი წყარო (`Single Source of Truth`).

### 3. ტექნიკური გამოწვევები და გადაწყვეტები (2 ქეისი)

- **ქეისი 1: მრავალდონიანი სთეითის მართვა და Prop Drilling-ის არიდება**
  - *პრობლემა:* ვიზიტების დაჯავშნის, სტატუსების ცვლილების და რეიტინგების მართვისას მონაცემების გადაცემა კომპონენტებს შორის (მშობლიდან შვილობილში 3-4 დონეზე) ართულებდა კოდის მხარდაჭერას.
  - *გადაწყვეტა:* დავნერგეთ Zustand Store, სადაც ყველა ძირითადი აქცია (`addAppointment`, `cancelAppointment`, `completeAppointment`) და მონაცემი თავმოყრილია ცენტრალურად. ნებისმიერ კომპონენტს შეუძლია პირდაპირ მიმართოს სთეითს Prop Drilling-ის გარეშე.

- **ქეისი 2: ოფლაინ რეჟიმი და სერვერის მიუწვდომლობის ფოლბექი (`isFallback`)**
  - *პრობლემა:* ქსელის შეფერხებისას ან Supabase სერვერთან კავშირის გაწყვეტისას აპლიკაცია იჭედებოდა ან აბრუნებდა ცარიელ ეკრანს.
  - *გადაწყვეტა:* შეიქმნა ავტომატური ფოლბექ მექანიზმი (`isFallback`), რომელიც სერვერის შეცდომის დაფიქსირებისას მომხმარებელს აწვდის ლოკალურ დემო მონაცემებს და აფრთხილებს ვიზუალურად (`TriangleAlert` კომპონენტით).
